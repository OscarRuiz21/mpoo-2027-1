0.1 · Instalar el JDK 21

El JDK es el kit que compila y ejecuta Java. Vamos con la versión 21, que es LTS (soporte extendido) y la que usa la industria hoy.

Opción rápida, en PowerShell:

winget install EclipseAdoptium.Temurin.21.JDK

Si winget no existe en tu equipo, descarga el instalador .msi desde adoptium.net y sigue el asistente. Deja marcada la casilla "Set JAVA_HOME variable" y "Add to PATH". Si la dejaste sin marcar, no reinstales: en la Parte 1 viene cómo agregarlo a mano.

Si tienes Homebrew:

brew install --cask temurin@21

Si no tienes Homebrew, descarga el .pkg desde adoptium.net (elige aarch64 si tu Mac es M1/M2/M3/M4, o x64 si es Intel) y sigue el asistente.

En Ubuntu (22.04 o más nuevo) o Debian 13:

sudo apt update
sudo apt install openjdk-21-jdk

En Debian 12 ese paquete no existe: usa el repo de Adoptium, igual que en Fedora (las instrucciones para deb están en adoptium.net/installation/linux).

En Fedora el repositorio oficial ya no trae Java 21 (solo 25 y más nuevos). Agrega el repo de Adoptium e instala Temurin 21:

sudo tee /etc/yum.repos.d/adoptium.repo <<'EOF'
[Adoptium]
name=Adoptium
baseurl=https://packages.adoptium.net/artifactory/rpm/fedora/$releasever/$basearch
enabled=1
gpgcheck=1
gpgkey=https://packages.adoptium.net/artifactory/api/gpg/key/public
EOF
sudo dnf install temurin-21-jdk

En Arch: sudo pacman -S jdk21-openjdk

0.2 · Instalar Git

winget install Git.Git

O el instalador de git-scm.com. Instala también Git Bash, que es la terminal que vamos a usar en clase.

Por qué Git Bash y no PowerShell

Con Git Bash, los comandos de Windows son idénticos a los de Mac y Linux. Así todos escribimos lo mismo y nadie se pierde. Ábrelo desde el menú Inicio buscando "Git Bash".

Lo más simple, en la Terminal:

xcode-select --install

Eso instala las herramientas de línea de comandos de Apple, que incluyen Git. Si prefieres la versión más nueva: brew install git.

sudo apt install git

En Fedora: sudo dnf install git · En Arch: sudo pacman -S git

El PATH, explicado desde cero

Cuando escribes java y das Enter, la terminal no adivina dónde está el programa: lo busca en una lista de carpetas, en orden, y ejecuta el primero que encuentre. Esa lista se llama el PATH. Si la carpeta donde quedó Java no está en la lista, la terminal contesta command not found aunque Java sí esté instalado. No hay nada roto: la terminal solo no sabe dónde buscar.

Puedes ver tu lista ahora mismo. Este comando la imprime, una carpeta por renglón, y es el mismo en los tres sistemas:

echo $PATH | tr ':' '\n'

Las dos reglas que explican casi todos los sustos

1 · Los instaladores agregan su carpeta al PATH por ti; por eso normalmente no lo tocas nunca. 2 · La terminal lee el PATH una sola vez, al abrirse. Después de cualquier cambio, la ventana que ya estaba abierta no se entera: cierra y abre una nueva.

Tu JDK quedó en C:\Program Files\Eclipse Adoptium\jdk-21…\bin (en Git Bash esa misma carpeta se ve como /c/Program Files/…; es la misma). El instalador la agrega al PATH solo. Lo que sigue es únicamente por si no quedó:

  1. Copia la ruta de la carpeta. Abre el Explorador de archivos → C:\Program Files\Eclipse Adoptium → entra a la carpeta que empieza con jdk-21 → entra a bin. Ahí debe estar java.exe. Haz clic en la barra de direcciones y copia la ruta completa (Ctrl + C).
  2. Menú Inicio → escribe variables → abre "Editar las variables de entorno del sistema" → botón Variables de entorno…
  3. Vas a ver dos listas. En la de abajo, Variables del sistema, selecciona Path → Editar… → Nuevo → pega la ruta → Aceptar en las tres ventanas. Si el equipo no te deja tocar la lista de abajo (pasa en máquinas sin permisos, como las del laboratorio), usa la de arriba, la de usuario: para ti funciona igual.
  4. Cierra todas las ventanas de Git Bash, abre una nueva y corre java -version.

En macOS no tienes que tocar el PATH para Java: el instalador deja el JDK en una carpeta que el sistema ya vigila, y el java de /usr/bin lo encuentra solo. Si java -version no responde, pregúntale al sistema qué JDKs está viendo:

/usr/libexec/java_home -V

Si tu JDK 21 no aparece en esa lista, la instalación no terminó: vuelve a correr el .pkg. Si sí aparece y aun así falla, avísame y lo resolvemos en el laboratorio.

En Linux no hay nada que hacer: apt, dnf y pacman dejan los programas en /usr/bin, que siempre está en el PATH. Solo si un día instalas algo a mano, descomprimiendo un .tar.gz, te toca agregar su carpeta bin al final de tu ~/.bashrc con una línea export PATH="…/bin:$PATH", y abrir una terminal nueva.

Parte 2 · Tu primer programa, sin IDE

Vamos a compilar y ejecutar a mano, con dos comandos. Después usaremos el IDE todo el semestre, pero primero hay que ver qué hace el compilador. El IDE hace esto mismo escondido detrás de un botón verde.

2.1 · Crear la carpeta y el archivo

# crea una carpeta para el curso y entra en ella
mkdir -p ~/mpoo
cd ~/mpoo

Ahora crea un archivo llamado HolaMundo.java con este contenido. Puedes usar el Bloc de notas, TextEdit, nano, o el editor que quieras:

public class HolaMundo {
    public static void main(String[] args) {
        System.out.println("Hola, mundo");
    }
}

El nombre del archivo importa

Tiene que llamarse exactamente HolaMundo.java, con la H y la M mayúsculas. En Java, el archivo debe llamarse igual que la clase pública que contiene. Es la primera regla del lenguaje que vas a romper sin querer, y hoy la rompemos a propósito para verla.

2.2 · Compilar

javac HolaMundo.java

Si todo salió bien, no imprime nada. En Unix el silencio es señal de éxito. Ahora mira qué apareció:

ls
Salida esperadaHolaMundo.class HolaMundo.java

Ese HolaMundo.class no lo escribiste tú: lo generó el compilador. No es código Java ni es un ejecutable de tu sistema: es bytecode, un lenguaje intermedio que entiende la máquina virtual de Java. Es la razón por la que el mismo archivo corre igual en Windows, Mac y Linux.

2.3 · Ejecutar

java HolaMundo
Salida esperadaHola, mundo

Fíjate en el detalle: al compilar escribiste HolaMundo.java con extensión, y al ejecutar escribiste HolaMundo sin extensión. No le pasas un archivo: le pasas el nombre de la clase que quieres correr.

2.4 · Rómpelo a propósito

Quítale el punto y coma a la línea del println, guarda y vuelve a compilar:

javac HolaMundo.java
Salida esperadaHolaMundo.java:3: error: ';' expected System.out.println("Hola, mundo") ^ 1 error

Lee el mensaje completo: te dice archivo, línea, qué esperaba y dónde. Vas a leer cientos de estos este semestre. El que aprende a leerlos avanza el triple. Vuelve a poner el punto y coma y compila otra vez.

2.5 · Lo mismo, ahora en el IDE

  1. Abre IntelliJ IDEA → New Project.
  2. Nómbralo hola-ide, elige Java y como SDK el 21 que instalaste.
  3. En src, clic derecho → New → Java Class → nómbrala HolaMundo.
  4. Escribe el mismo main y dale al triángulo verde.

Mira la ventana de abajo cuando corre: ahí está el mismo javac y el mismo java que acabas de escribir a mano. El IDE no hace magia, escribe los comandos por ti.

Parte 3 · Git: dónde va a vivir tu trabajo

3.1 · Cómo funciona el repositorio del curso

Todo el material del curso vive en un repositorio público de GitHub. Yo subo ahí las guías y el código de apoyo; ustedes suben ahí sus entregas.

mpoo-2027-1/ ├── guias/ # las guías de laboratorio (las subo yo) ├── apoyo/ # código de ejemplo de cada tema (lo subo yo) └── entregas/ # aquí van sus prácticas ├── ramirez/ │ ├── lab00/ │ └── p01/ └── cruz/ └── lab00/

Cada quien toca solo su carpeta. Por eso 27 personas pueden trabajar en el mismo repositorio sin pisarse.

3.2 · Presentarte con Git

Git firma cada cambio con tu nombre. Configúralo una sola vez en tu vida:

git config --global user.name "Tu Nombre Completo"
git config --global user.email "el-correo-de-tu-cuenta-de-github@ejemplo.com"

Usa el mismo correo de tu cuenta de GitHub

Si pones otro, tus commits aparecen como de un desconocido y no se te acreditan. Y esa acreditación es justamente la evidencia de trabajo en equipo que se califica en el proyecto final.

3.3 · Hacer tu copia (fork)

No vas a escribir directo en mi repositorio: vas a trabajar en tu propia copia. Así no puedes romper nada de nadie.

  1. Entra al repositorio del curso (te paso el enlace en clase).
  2. Arriba a la derecha, botón Fork → Create fork.
  3. Ya tienes github.com/TU-USUARIO/mpoo-2027-1. Es tuyo.

3.4 · Bajarlo a tu computadora (clone)

En tu fork, botón verde Code → copia la URL HTTPS. Luego:

cd ~/mpoo
git clone https://github.com/TU-USUARIO/mpoo-2027-1.git
cd mpoo-2027-1

Comprueba que estás parado en el lugar correcto:

git status
Salida esperadaOn branch main Your branch is up to date with 'origin/main'. nothing to commit, working tree clean

"nothing to commit, working tree clean" quiere decir: no has cambiado nada todavía. Vas a ver ese mensaje mil veces.

4.3 · Subirlo (push)

git push

La primera vez, Git te va a abrir el navegador para autorizar la conexión con GitHub (lo hace el Git Credential Manager, que vino con Git for Windows). Inicia sesión, dale Authorize, y no necesitas nada más. Si en vez del navegador la terminal te pide contraseña, sigue los pasos de abajo.

Cómo les subo el material nuevo

Cada semana subo la guía y el código de apoyo al repositorio del curso. Como ustedes trabajan en un fork, hay que sincronizarlo para recibir lo nuevo. Es un botón:

  1. Entra a tu fork en GitHub.
  2. Si dice "This branch is behind…", dale a Sync fork → Update branch.
  3. En tu terminal, baja los cambios:
git pull

Hazlo al inicio de cada laboratorio. Te toma cinco segundos y te evita trabajar con la guía vieja.

Los cuatro errores de siempre

Lo que pasaQué significa y qué haces
nothing to commit después del addNo guardaste el archivo en el editor, o lo pusiste en otra carpeta. Corre git status y revisa la ruta.
Hiciste commit pero no aparece en GitHubFalta el push. El commit guarda en tu computadora; el push lo sube. Es el error número uno.
rejected … fetch first al hacer pushHay algo en GitHub que no tienes abajo. Corre git pull y vuelve a intentar el push.
Te pide contraseña y la rechazaLa contraseña de GitHub no sirve para push. Usa tu token (Parte 4.3). Si lo perdiste, genera otro.

Si te atoras y no sabes qué hiciste

No borres la carpeta ni vuelvas a clonar. Corre git status, tómale captura y mándamela. Casi siempre son dos comandos para salir, y aprender a leer git status vale más que cualquier atajo.
