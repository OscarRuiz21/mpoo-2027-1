Tu sistema

Cómo funciona la entrega en este curso

Hay un solo repositorio para todo el grupo y tú eres colaborador: trabajas directo en él, sin copias ni forks. La rama main está protegida (nadie puede escribirle directamente, ni tú ni por accidente), así que cada práctica viaja así:

main (protegida, aquí vive lo aceptado) │ ├──▸ creas tu rama p03-ramirez │ trabajas, guardas commits ahí │ la subes con push │ abres un pull request ← esa es tu entrega │ ◂── yo lo reviso y lo integro a main

Así entregan los equipos profesionales, y es lo que vas a poner en tu currículum: un semestre entero trabajando con ramas y pull requests en un repositorio compartido.

Solo la primera vez

Esto ya lo hiciste en el Laboratorio 0. Está aquí por si estrenas máquina o algo se perdió:

  1. Preséntate con Git (con tu nombre real y el correo de tu cuenta de GitHub): 
    git config --global user.name "Ana Ramírez"
git config --global user.email "tu-correo@ejemplo.com"
  2. Sé colaborador. Me mandas tu usuario (usuario: fulanito123) y te llega una invitación al correo de tu cuenta: acéptala. Sin esto, GitHub te va a rechazar el push.
  3. Clona el repositorio del curso: 
    mkdir -p ~/mpoo && cd ~/mpoo
git clone https://github.com/OscarRuiz21/mpoo-2027-1.git
cd mpoo-2027-1

Rutina de entrega

De la práctica 1 a la 12 · siempre igual

0
Antes de empezar: trae lo nuevo
cd ~/mpoo/mpoo-2027-1   git checkout main   git pull
Baja la guía y el código de apoyo que subí esta semana. Cinco segundos y te evita trabajar con la guía vieja.
1
git checkout -b pNN-apellido
Tu rama de la práctica. Nunca trabajas en main: está protegida y no te va a dejar. Ejemplo: p03-ramirez.
2
Trabaja
Tu código va en entregas/apellido_nombre/pNN/. Nunca toques la carpeta de otro ni guias/ ni apoyo/.
3
git status
¿Qué cambió? Míralo siempre antes de guardar. Si aparece un archivo que no esperabas, ahí lo cachas.
4
git add entregas/apellido_nombre/pNN
Preparo lo que quiero guardar. Nombra tu carpeta, no uses git add .: eso agarra todo lo que haya, incluida basura del IDE.
5
git commit -m "P03: arreglos y arreglos multidimensionales"
Lo guardo con un mensaje que explique qué hice. Empieza con el número de práctica. Un mensaje como "cambios" o "asdf" no le sirve a nadie, empezando por ti en noviembre.
6
git push -u origin pNN-apellido
Subo mi rama a GitHub. El -u origin … solo la primera vez que subes esa rama; después basta git push. Sin push no hay nada.
7
Abre tu PR y comprueba
En el repo del curso: Compare & pull request → título PNN · Apellido → Create. Tu entrega es el PR, y la hora que cuenta es la de tu último push.

Dónde va tu código

Tu carpeta usa tu primer apellido y tu primer nombre, en minúsculas y sin acentos, unidos por guion bajo, y adentro una carpeta por práctica:

mpoo-2027-1/ ├── guias/ ← material que yo subo: se lee, no se toca ├── apoyo/ ← código de apoyo: igual └── entregas/ └── ramirez_ana/ ← apellido_nombre, la tuya ├── p01/ │ └── HolaMundo.java ├── p02/ │ └── … └── p03/

El pull request, en corto

  • Título: PNN · Apellido, por ejemplo P03 · Ramírez. En la descripción, una línea de qué hiciste.
  • La hora que cuenta es la de tu último push a la rama, no la de abrir el PR.
  • ¿Te faltó un archivo? No abras otro PR: guarda, git add, commit y push en la misma rama. El PR se actualiza solo con todo lo nuevo.
  • Después: yo lo reviso y lo integro a main. GitHub borra tu rama al integrarla y eso es normal: la próxima práctica empieza con el paso 0 y una rama nueva.

La contraseña que no es contraseña

La primera vez que haces push en una máquina, Git te abre el navegador para autorizar la conexión con GitHub. Inicia sesión, dale Authorize y listo, no vuelve a preguntar. Si en vez del navegador la terminal te pide contraseña, necesitas un token: los pasos están en la Parte 4.4 del Laboratorio 0.

La primera vez que haces push en una máquina, la terminal pide usuario y contraseña, pero la contraseña de GitHub ya no funciona ahí: se usa un token que generas una vez y guardas en tus notas. Los pasos exactos están en la Parte 4.4 del Laboratorio 0.

Los errores de siempre

Lo que pasaQué significa y qué haces
nothing to commit después del addNo guardaste el archivo en el editor, o lo pusiste en otra carpeta. Corre git status y revisa la ruta.
Hiciste commit pero no aparece en GitHubFalta el push. El commit guarda en tu computadora; el push lo sube. Es el error número uno.
protected branch al hacer pushCommiteaste en main sin querer. No pasa nada: corre git checkout -b pNN-apellido; la rama nueva se lleva tus commits, y desde ahí pusheas normal.
Olvidaste el -u origin … en el primer pushGit te lo dice con el comando exacto en pantalla. Cópialo y córrelo: es eso.
Te pide contraseña y la rechazaLa contraseña de GitHub no sirve para push: usa tu token (sección de arriba). Si lo perdiste, genera otro.
GitHub rechaza tu push con 403 o "permission denied"Casi seguro no has aceptado la invitación de colaborador. Revisa el correo de tu cuenta de GitHub (y el spam), o entra a github.com/OscarRuiz21/mpoo-2027-1/invitations.
Your branch is behind 'origin/main'Estás parado en main y te falta lo nuevo: git pull. Es exactamente el paso 0.

Si te atoras y no sabes qué hiciste

No borres la carpeta ni vuelvas a clonar. Corre git status, tómale captura y mándamela. Casi siempre son dos comandos para salir, y aprender a leer git status vale más que cualquier atajo.

Mini glosario

PalabraQué es
repositorioLa carpeta del proyecto con toda su historia de cambios adentro.
clonarBajar el repositorio completo a tu máquina, historia incluida. Se hace una vez.
ramaUna línea de trabajo aparte: lo que hagas ahí no toca lo de nadie hasta que se integra.
commitUna fotografía de tus cambios, guardada en tu máquina con un mensaje que la explica.
pushSubir tus commits a GitHub. Hasta el push, nadie más los ve.
pullTraer a tu máquina lo nuevo que hay en GitHub.
pull request (PR)"Aquí está mi rama, revísenla e intégrenla." En este curso, tu entrega.
mergeIntegrar una rama en otra. Lo hago yo al aceptar tu PR, y tu trabajo pasa a main.
