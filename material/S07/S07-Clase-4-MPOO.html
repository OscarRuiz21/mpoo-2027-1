Anatomía · 1 · la variable, por partes
double  saldo  = 1500.75;
tipo: qué cabe adentro nombre: cómo la llamo valor: qué tiene ahora
  • Declarar es crear la cajita: double saldo;
  • Inicializar es darle su primer valor: saldo = 0;
  • Asignar es cambiarlo después: saldo = 900;
  • El tipo se elige una vez y no cambia. Java es de tipado estático: si la declaraste double, double se queda toda su vida.
Y una variable puede vivir en tres lugares
public class Cuenta {
    double saldo;                // ATRIBUTO: lo que el objeto sabe

    void abonar(double monto) {   // PARAMETRO: llega de fuera
        double nuevo = saldo + monto;  // LOCAL: solo aqui
        saldo = nuevo;
    }
}

Todo atributo es una variable, pero no toda variable es atributo: las locales y los parámetros también lo son. Hoy nada más los nombramos; cuánto vive cada uno lo vemos en la segunda mitad, en ámbito.

Y todos los tipos caen en una de dos familias. Primitivos: la cajita guarda el valor mismo. Referencias: la cajita guarda a cuál objeto apunta, y si no apunta a ninguno vale null. Los ocho primitivos y las referencias los vemos en la segunda mitad; por ahora quédense con que la cajita puede guardar un valor o una dirección.

Anatomía · 2 · el atributo, por partes
private  double  saldo  = 0;
modificador (opcional): lo nuevo, llega con encapsulamiento tipo nombre valor inicial (opcional)

Es el mismo despiece de la slide anterior, con una parte más. El atributo es la variable que va en la clase: por eso admite modificador y por eso nace con valor por defecto. Nombre en camelCase, sustantivo y sin abreviar: velocidad, no vel ni v1.

¿Y si el tipo no es primitivo? Entonces el atributo es un objeto
public class Alumno {
    double promedio;   // primitivo: nace en 0.0
    String nombre;     // objeto: nace en null
    Materia favorita;  // otro objeto tuyo: null
}

null no es cero ni cadena vacía: es "todavía no apunta a ningún objeto". El atributo existe; lo que no existe es el objeto del otro lado. Por eso, antes de usarlo, hay que crearlo: a.nombre = "Ana"; o a.favorita = new Materia();

Exception in thread "main" java.lang.NullPointerException:
Cannot invoke "String.length()" because "<local1>.nombre" is null

Este no lo caza el compilador: truena al correr. Es el precio de que el atributo sea una referencia.

Anatomía · 3 · el método, por partes
public void retirar(double monto) { ... }
cabecera: todo lo de antes de las llaves firma: nombre + TIPOS de los parámetros cuerpo: lo que va entre llaves

La firma es retirar(double)

Y nada más. El tipo de retorno NO es parte de la firma en Java. Tampoco el nombre del parámetro ni los modificadores.

Por eso esto no compila

void area() { ... }   // misma firma: area()

Anatomía · 3 · el vocabulario que se les va a pedir
// en la clase (la cabecera):
void retirar(double monto) { ... }
              ↑ PARAMETRO (formal)

// en el main (la invocacion):
cuenta.retirar(500.0);
               ↑ ARGUMENTO (el valor real)

Invocación: objeto.metodo(argumentos). El objeto va primero porque el método le pertenece a él.

Valor de retorno

void significa que no devuelve nada: cambia el estado y ya. Si el método declara cualquier otro tipo, tiene que haber un return de ese tipo en todos los caminos.

Regla práctica para decidir: si quien llama necesita un dato de vuelta, el método retorna. Si solo debe cambiar el objeto, es void.

Mismo nombre y firma distinta se llama sobrecarga, y es legal. En la siguiente slide la van a ver trabajando, con los constructores.

Anatomía · 4 · el constructor, por partes
public Coche(double velocidad, double gasolina) { ... }
el MISMO nombre de la clase, con la misma mayúscula SIN tipo de retorno, ni siquiera void parámetros, como cualquier método 
public class Coche {
    double velocidad;
    double gasolina;

    // firma: Coche(double, double)
    Coche(double velocidad, double gasolina) {
        this.velocidad = velocidad;
        this.gasolina = gasolina;
    }

    // firma: Coche()  ·  otra firma = sobrecarga
    Coche() {
        this.velocidad = 0;
        this.gasolina = 40;
    }
}
  • Para qué existe: para que el objeto nazca completo. Sin él, nace con los valores por defecto y hay que irle poniendo atributo por atributo.
  • Cuándo corre: una sola vez, en el instante del new. No se invoca a mano.
  • Qué es this: "este objeto". this.velocidad es el atributo; velocidad a secas es el parámetro. Se usa cuando los dos se llaman igual.
  • Sobrecarga, ahora sí: dos constructores pueden convivir porque tienen firmas distintas: Coche(double, double) y Coche().

Si no escribes ninguno, Java te regala uno vacío y por eso new Coche() funciona desde el día uno. En cuanto escribes el tuyo, ese regalo desaparece.

Anatomía · 4 · el constructor en acción, y sus tres trampas
Sin constructor: el objeto nace vacío y tú lo llenas
Coche c = new Coche();
c.velocidad = 30.5;
c.gasolina  = 12.0;   // si la olvidas: 0.0
Con constructor: nace completo, en una línea
Coche a = new Coche(30.5, 12.0);
Coche b = new Coche();      // el otro
a: velocidad=30.5 gasolina=12.0 b: velocidad=0.0 gasolina=40.0

Tres cosas que definen a un constructor: se llama exactamente como la clase, no lleva tipo de retorno (ni void), y corre una sola vez, en el instante del new. Después ya nadie lo vuelve a llamar.

1 · Olvidar el this

Coche(double velocidad) {
    velocidad = velocidad;  // a si mismo
}

Compila sin una queja y el atributo se queda en 0.0. Con this.velocidad = velocidad; sí funciona.

2 · Escribir uno y seguir usando el vacío

error: constructor Vacio in class Vacio
cannot be applied to given types;
required: double · found: no arguments

Si escribes un constructor con parámetros, el vacío ya no existe: o lo llamas con sus datos, o escribes también el vacío.

void Coche(double v) { ... }

Eso no es un constructor: es un método que se llama igual que la clase. Compila, nunca corre con new, y los atributos quedan en cero.

La radiografía · el modelo en 4 líneas, antes de teclear

Cuatro líneas de comentario arriba de cada clase. No son adorno: es la parte que la P2 dejó ver que falta.

  • CONTEXTO: ¿en qué programa vive este objeto?
  • QUÉ SABE Y POR QUÉ: cada atributo, con su razón.
  • QUÉ SABE HACER Y POR QUÉ: cada método: por qué void o por qué retorna, y por qué esos parámetros.
  • QUÉ IGNORÉ: una o dos cosas del objeto real que no modelé, y por qué.

¿Atributo o parámetro?

Una sola pregunta: ¿el dato le pertenece al objeto o se lo dan en el momento?

La regla del curso

Usen int para enteros y double para decimales, boolean para sí o no y char para un carácter. Los otros cuatro existen y hay que saber que existen; se usan cuando hay una razón (memoria, precisión, una API que los pide).

= no es ==

= asigna, == pregunta. if (x = 5) ni siquiera compila en Java, y eso es una suerte: en C compila y arruina la tarde. Y el corto circuito: si promedio >= 6.0 es falso, Java ya ni mira las faltas.

Nunca comparen double con ==

0.1 + 0.2 imprime 0.30000000000000004. No es un error de Java: es cómo se guardan los decimales en binario. Se compara con una tolerancia, no con ==.

En Java no hay variables globales

Vienen de C buscando ese lugar y no existe. Lo más parecido es un atributo static, que pertenece a la clase y se llama por su nombre: Coche.totalCoches. Toda variable vive dentro de una clase.

Variables · static y final, exprés

static · de la clase, no del objeto

El dato es uno solo y lo comparten todos los objetos. Se accede por el nombre de la clase.

static int totalCoches = 0;
// dentro del constructor o de un metodo:
totalCoches++;
// desde fuera:
Coche.totalCoches

final · se asigna una vez

Es una constante. Por convención va en MAYÚSCULAS con guion bajo. Si intentan reasignarla, el compilador los detiene.

static final double IVA = 0.16;
final int RUEDAS = 4;

Los dos juntos, static final, son la forma normal de escribir una constante en Java: Math.PI es exactamente eso.

Todo junto · así se ve dentro de una clase de verdad
public class Termometro {
    static final double LIMITE_FIEBRE = 38.0;  // constante
    static int medicionesTotales = 0;          // de CLASE

    double celsius = 36.5;   // de INSTANCIA
    int lecturas = 0;
    // firma: medir(double) · retorno: void
    void medir(double nuevaTemp) {
        celsius = nuevaTemp;
        lecturas++;
        medicionesTotales++;
    }
    // firma: enFahrenheit() · retorno: double
    double enFahrenheit() {
        return celsius * 9 / 5.0 + 32;   // 5.0, no 5
    }
    // firma: hayFiebre(double) · retorno: boolean
    boolean hayFiebre(double limite) {
        return celsius >= limite && lecturas > 0;
    }
}
Dónde quedó cada cosa de hoy
  • Tipos: double para la temperatura, int para contar, boolean para el sí o no.
  • Constante: static final en MAYÚSCULAS.
  • Ámbito: medicionesTotales es de la clase; celsius y lecturas, de cada objeto.
  • Operadores: aritméticos en enFahrenheit, relacional y lógico en hayFiebre. El casting va en el main.
