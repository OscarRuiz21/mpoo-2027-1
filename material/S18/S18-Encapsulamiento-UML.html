Getter para leer, setter para cambiar

⏱ ~19 min
Ana recibe un aumento. sueldoBase es private. ¿Cómo lo cambiamos?
Setters · La idea

Un setter cambia un atributo privado, si el valor sirve

  • El getter deja leer: getSueldoBase().
  • El setter deja cambiar: setSueldoBase(25000).
  • El setter revisa antes: si el valor no sirve, no cambia nada.
  • Mejor aún: un método que dice qué pasa, como aumentar(10).
AnalogíaEl cajero automático: no tienes un botón «poner saldo». Tienes depositar y retirar, y cada uno revisa antes.
Sin la revisión, un setter es un public disfrazado.
Setters · ¿Getter y setter para todo?

No: cada atributo se piensa

Atributo¿Getter?¿Setter?Por qué
nombreSíNoNo cambia después de crear al empleado (en un momento: final)
sueldoBaseSíMejor aumentar()El cambio tiene reglas de negocio
bonoSíSí, con validaciónCambia cada trimestre, pero nunca negativo
cuentaNoNoNadie de afuera toca la cuenta (ya lo verán: composición)
IntelliJ genera getters y setters con un clic. Que los genere no quiere decir que todos sirvan.
Setters · El primer intento

Un setter que solo asigna

Empleado.java
class Empleado {    private String nombre;    private double sueldoBase;     Empleado(String nombre, double sueldoBase) {        this.nombre = nombre;        this.sueldoBase = sueldoBase;    }     public double getSueldoBase() { return sueldoBase; }     public void setSueldoBase(double sueldoBase) {        this.sueldoBase = sueldoBase;    }}
Main.java
public class Main {    public static void main(String[] args) {        Empleado e = new Empleado("Ana", 20000);        e.setSueldoBase(-5000);        System.out.println(e.getSueldoBase());    }}
Consola
-5000.0
Volvimos al sueldo negativo. Un setter sin validación es un public disfrazado.
Setters · El setter que cuida

El setter revisa antes de cambiar

Empleado.java
class Empleado {    private String nombre;    private double sueldoBase;     Empleado(String nombre, double sueldoBase) {        this.nombre = nombre;        setSueldoBase(sueldoBase);    }     public double getSueldoBase() { return sueldoBase; }     public void setSueldoBase(double sueldoBase) {        if (sueldoBase < 0) {            System.out.println("Rechazado: " + sueldoBase);            return;        }        this.sueldoBase = sueldoBase;    }}
Main.java
public class Main {    public static void main(String[] args) {        Empleado e = new Empleado("Ana", 20000);        e.setSueldoBase(-5000);        System.out.println(e.getSueldoBase());        e.setSueldoBase(25000);        System.out.println(e.getSueldoBase());    }}
Consola
Rechazado: -5000.0
20000.0
25000.0
Si el valor no sirve, el setter avisa y no toca nada. El sueldo anterior se queda.
Setters · Una sola regla

El constructor también usa el setter

Empleado.java
class Empleado {    private String nombre;    private double sueldoBase;     Empleado(String nombre, double sueldoBase) {        this.nombre = nombre;        setSueldoBase(sueldoBase);    }     public double getSueldoBase() { return sueldoBase; }     public void setSueldoBase(double sueldoBase) {        if (sueldoBase < 0) {            System.out.println("Rechazado: " + sueldoBase);            return;        }        this.sueldoBase = sueldoBase;    }}
  • La regla «no negativo» vive en un solo lugar: el setter.
  • El constructor no repite el if: llama a setSueldoBase.
  • Si mañana cambia (sueldo mínimo de 8 000), se corrige una línea.
  • Si se crea con un valor inválido, el setter también lo rechaza.
Constructor y setter pasan por la misma puerta.

Setters · Mejor que un setter

Un método que dice qué hace

Empleado.java
class Empleado {    private String nombre;    private double sueldoBase;     Empleado(String nombre, double sueldoBase) {        this.nombre = nombre;        this.sueldoBase = sueldoBase;    }     public double getSueldoBase() { return sueldoBase; }     public void aumentar(double porcentaje) {        if (porcentaje <= 0 || porcentaje > 30) {            System.out.println("No permitido: " + porcentaje);            return;        }        sueldoBase = sueldoBase * (1 + porcentaje / 100);    }}
Main.java
public class Main {    public static void main(String[] args) {        Empleado e = new Empleado("Ana", 20000);        e.aumentar(10);        e.aumentar(80);        System.out.println(e.getSueldoBase());    }}
Consola
No permitido: 80.0
22000.0
setSueldoBase(22000) dice cómo; aumentar(10) dice qué. El objeto pone las reglas del negocio.

Paquetes y los cuatro modificadores

⏱ ~25 min
Hasta hoy todas sus clases vivían en una sola carpeta. ¿Qué pasa cuando el proyecto crece?
Paquetes · Un paquete

Un paquete es una carpeta con nombre

Proyecto en IntelliJ
S18-Nomina/
└── src/
    ├── nomina/
    │   ├── Empleado.java
    │   └── Gerente.java
    ├── bonos/
    │   └── Vendedor.java
    └── app/

  • Agrupa clases que trabajan juntas.
  • Dos clases pueden llamarse igual en paquetes distintos: nomina.Empleado y rh.Empleado.
  • Nombres en minúsculas; la carpeta y el paquete se llaman igual.
AnalogíaLa dirección postal: hay muchas calles Juárez, pero solo una en tu colonia.
Hasta hoy todas sus clases vivían juntas en una sola carpeta: el paquete sin nombre.

final: lo que ya no cambia

⏱ ~8 min
El nombre de un empleado no cambia. ¿Cómo se lo decimos a Java?
final · Tres usos

final quiere decir «ya no»

DóndeQuiere decirEjemplo
AtributoSe asigna una vez, en el constructor, y ya no cambiaprivate final String nombre;
MétodoLas hijas no lo pueden sobrescribirpublic final String getNombre()
ClaseNadie puede heredar de ellaString es final
AnalogíaTinta indeleble contra lápiz: lo final no se borra; lo demás, sí.
Se usa para lo que no debe cambiar, no para todo.
final · final en un atributo

Un setter de nombre ya no compila

javac

  value to final variable nombre
El constructor lo asigna una vez. Después, ni la propia clase lo cambia.

«Tiene un»: composición

⏱ ~13 min
¿Qué hacemos cuando «es un» suena mal?
Composición · La idea

Composición: un objeto que tiene a otro

  • Una clase guarda como atributo un objeto de otra clase.
  • Le delega trabajo: no lo hace ella, se lo pide al otro.
  • Se reconoce con la frase «tiene un»; la herencia, con «es un».
AnalogíaEl celular tiene una batería: no es una batería, pero viene con ella y la usa para todo.
Herencia y composición son las dos formas de reutilizar código.
Composición · Es un o tiene un

La prueba de la frase

Frase¿Suena bien?Se modela con
Un Gerente es un EmpleadoSíHerencia: extends
Un Empleado es una CuentaBancariaNo—
Un Empleado tiene una CuentaBancariaSíComposición: un atributo
Un Auto tiene un MotorSíComposición: un atributo
Cuando «es un» suena raro y «tiene un» suena bien, no es herencia.
Composición · En código

Un atributo que es otro objeto

Empleado.java
abstract class Empleado {    private final String nombre;    private final double sueldoBase;    private final CuentaBancaria cuenta;     Empleado(String nombre, double sueldoBase) {        this.nombre = nombre;        this.sueldoBase = sueldoBase;        this.cuenta = new CuentaBancaria();    }     public String getNombre() { return nombre; }    public double getSueldoBase() { return sueldoBase; }    public double getSaldo() { return cuenta.getSaldo(); }     public void cobrar() {        cuenta.depositar(calcularPago());    }     public abstract double calcularPago();}
CuentaBancaria.java
class CuentaBancaria {    private double saldo;     public void depositar(double monto) {        if (monto <= 0) {            return;        }        saldo = saldo + monto;    }     public double getSaldo() { return saldo; }}
  • La cuenta nace con el empleado: new en el constructor.
  • Es private final: nadie de afuera la toca.
  • cobrar() le delega el depósito a su cuenta.
Empleado no sabe depositar: le pide a su cuenta que lo haga.

Del enunciado al diagrama

Una estación de monitoreo tiene un nombre y uno o más sensores. Todo sensor tiene un id, sabe medir() y tiene su propia batería con un porcentaje de carga. Hay sensores de temperatura y de humedad, y cada uno mide a su manera. Si la estación se desmonta, los sensores se pueden instalar en otra.
En papel o en draw.io: subrayen los sustantivos (clases) y busquen cada «es un» y cada «tiene un». Foto al chat.
Solución · Paso 1

Las clases: los sustantivos del enunciado

Sensor en cursiva: no existe un sensor «a secas», solo de temperatura o de humedad.
Solución · Paso 2

«Es un»: dos generalizaciones

Un SensorTemperatura es un Sensor. Cada hijo escribe su medir().
Solución · Paso 3

«Tiene una» batería: composición

La batería nace con el sensor (new en su constructor) y es solo suya.
Solución · Paso 4

«Tiene sensores»: agregación, 1..*

Los sensores llegan de afuera y sobreviven a la estación: rombo hueco.
Solución · En Java

La jerarquía y la batería

Sensor.java
abstract class Sensor {    private final String id;    private final Bateria bateria;     Sensor(String id) {        this.id = id;        this.bateria = new Bateria();    }     public String getId() { return id; }    public int getCarga() { return bateria.getPorcentaje(); }     public abstract double medir();}
Bateria.java
class Bateria {    private int porcentaje = 100;     public int getPorcentaje() { return porcentaje; }}
SensorTemperatura.java
class SensorTemperatura extends Sensor {    SensorTemperatura(String id) { super(id); }     @Override    public double medir() { return 21.5; }}
SensorHumedad.java
class SensorHumedad extends Sensor {    SensorHumedad(String id) { super(id); }     @Override    public double medir() { return 40.0; }}
Generalización = extends; composición = new Bateria() dentro del constructor de Sensor.
Solución · En Java

La estación y su main, y corre

Estacion.java
class Estacion {    private final String nombre;    private final Sensor[] sensores;     Estacion(String nombre, Sensor[] sensores) {        this.nombre = nombre;        this.sensores = sensores;    }     public void reportar() {        System.out.println("Estación " + nombre);        for (Sensor s : sensores) {            System.out.println(s.getId() + ": " + s.medir() + " (" + s.getCarga() + " %)");        }    }}
Main.java
public class Main {    public static void main(String[] args) {        Sensor[] sensores = {            new SensorTemperatura("T1"),            new SensorHumedad("H1")        };        Estacion azotea = new Estacion("Azotea", sensores);        azotea.reportar();    }}
Consola
Estación Azotea
T1: 21.5 (100 %)
H1: 40.0 (100 %)
Agregación = los sensores llegan por el constructor de Estacion: se crean afuera y sobreviven a ella.

✋ Pregunta · salida

La batería no puede pasar de 100 %

Escribe en Bateria los métodos cargar(int cuanto) y gastar(int cuanto).
Nunca debe quedar arriba de 100 ni abajo de 0, y no se vale pasar un número negativo.
Es el setter que valida de hoy, con dos métodos con intención. En el chat o en su cuaderno.
Pregunta de salida · Respuesta

Dos métodos que cuidan los límites

Bateria.java
class Bateria {    private int porcentaje = 100;     public int getPorcentaje() { return porcentaje; }     public void cargar(int cuanto) {        if (cuanto <= 0) {            return;        }        porcentaje = Math.min(100, porcentaje + cuanto);    }     public void gastar(int cuanto) {        if (cuanto <= 0) {            return;        }        porcentaje = Math.max(0, porcentaje - cuanto);    }}
Main.java
public class Main {    public static void main(String[] args) {        Bateria b = new Bateria();        b.gastar(70);        b.cargar(50);        System.out.println(b.getPorcentaje());        b.cargar(-500);        System.out.println(b.getPorcentaje());    }}
Consola
80
80
Sin setPorcentaje: nadie de afuera puede poner 150.
