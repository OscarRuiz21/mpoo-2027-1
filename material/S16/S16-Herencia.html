La cápsula: proteger lo de adentro

⏱ ~10 min

Acto 1 · Así escribimos clases hasta hoy

Atributos sin protección

Empleado.java
class Empleado {    String nombre;    double sueldoBase;     Empleado(String nombre, double sueldoBase) {        this.nombre = nombre;        this.sueldoBase = sueldoBase;    }}
Main.java

Consola
-5000.0
Cualquier clase puede escribir cualquier valor en el atributo, incluso un sueldo negativo.
Acto 1 · La cápsula

private: solo la propia clase toca el atributo

Empleado.java
class Empleado {    private String nombre;    private double sueldoBase;     Empleado(String nombre, double sueldoBase) {        if (sueldoBase < 0) {            sueldoBase = 0;        }        this.nombre = nombre;        this.sueldoBase = sueldoBase;    }     public String getNombre() { return nombre; }    public double getSueldoBase() { return sueldoBase; }}
  • private: el atributo solo se lee y se escribe dentro de Empleado.
  • El constructor decide qué valores son válidos.
  • Los getters dejan ver el valor sin poder cambiarlo.
El objeto ya se puede defender: los datos entran por el constructor y salen por los getters.
Acto 1 · Lo que dice el compilador

Acto 5

Object, toString y @Override

⏱ ~15 min
Todas las clases tienen un abuelo, aunque nunca lo escriban.
Acto 5 · Algo raro

Imprimimos un Gerente…

Main.java
public class Main {    public static void main(String[] args) {        Gerente g = new Gerente("Ana", 30000, 8000);        System.out.println(g);    }}
Consola
Gerente@6d06d69c
Nunca escribimos un método que imprima eso. ¿De dónde salió?
Acto 5 · El abuelo de todos

Toda clase hereda de Object

  • Si no escribes extends, Java pone extends Object.
  • Por eso todo objeto ya tiene toString().
  • El de Object imprime Clase@número: no sabe nada de nóminas.
El número después de @ cambia en cada corrida. No lo memoricen.
Acto 5 · Sobrescribir

@Override: el hijo cambia lo que heredó

Empleado.java
class Empleado {    // ...    @Override    public String toString() {        return nombre + " · base " + sueldoBase;    }}
Gerente.java
class Gerente extends Empleado {    // ...    @Override    public String toString() {        return super.toString() + " · bono " + bono;    }}
Consola
Eva · base 15000.0
Ana · base 30000.0 · bono 8000.0
Empleado sobrescribe el toString de Object. Gerente reutiliza el de su padre con super.toString() y agrega el bono.
Acto 5 · La red de seguridad

@Override revisa que la firma sea exacta

Con @Override y tostring en minúscula

Gerente.java
    @Override    public String tostring() {        return super.toString() + " · bono " + bono;    }
javac
error: method does not override or implement
  a method from a supertype

Sin @Override, mismo error de dedo

Gerente.java
    public String tostring() {        return super.toString() + " · bono " + bono;    }
Consola
Ana · base 30000.0
Con @Override, javac te avisa. Sin él compila, el bono desaparece y nadie te dice nada.
✋ Pregunta · acto 5

¿Qué hace @Override?

a) Hace que el método del padre se ejecute primero
b) Le pide a javac que confirme que estás sobrescribiendo un método heredado
c) Es obligatorio: sin él, el método no sobrescribe
Piensa en la lámina anterior: ¿qué pasó sin @Override?
Acto 5 · Respuesta

b) Es una revisión, no un permiso

  • La (a) es falsa: el método del padre solo corre si lo llamas con super.metodo().
  • La (c) es falsa: sin @Override, si la firma es exacta, sí sobrescribe. Pero si te equivocas, nadie te avisa.
  • Por eso, en este curso siempre se escribe @Override.
Regla del curso: cada vez que sobrescribas, escribe @Override.

Acto 6 · La idea

abstract: una clase que solo sirve para heredar

Empleado.java
abstract class Empleado {    private String nombre;    private double sueldoBase;// ...     public abstract double calcularPago(); // ...}
  • abstract class: no se pueden crear objetos de ella.
  • abstract double calcularPago(); no tiene cuerpo, termina en ;.
  • Es un contrato: cada hijo debe escribir su calcularPago().
La clase abstracta dice qué deben saber hacer todos sus hijos, pero no cómo.
Acto 6 · Lo que cambia

new Empleado(...) ya no compila

Main.java
        Empleado e = new Empleado("Eva", 15000);
javac
Main.java:3: error: Empleado is abstract; cannot be instantiated
Ya no existe el «empleado a secas»: solo Gerentes y Vendedores.
Acto 6 · El contrato

Un hijo que no cumple no compila

Vendedor.java
class Vendedor extends Empleado {    private double ventas;     Vendedor(String nombre, double sueldoBase, double ventas) {        super(nombre, sueldoBase);        this.ventas = ventas;    }}
javac
error: Vendedor is not abstract and does not
  override abstract method calcularPago()
  in Empleado
AnalogíaUn contrato de trabajo: el puesto puede cambiar, pero la cláusula «calcular tu pago» la firma todo el mundo.
Al Vendedor le falta calcularPago(). javac no lo deja pasar.
Acto 6 · Cada quien cumple a su manera

Gerente y Vendedor implementan calcularPago()

Gerente.java
class Gerente extends Empleado {    // ...    @Override    public double calcularPago() {        return getSueldoBase() + bono;    }// ...}
Vendedor.java
class Vendedor extends Empleado {    // ...    @Override    public double calcularPago() {        return getSueldoBase() + ventas * 0.05;    }// ...}
Usan getSueldoBase() porque sueldoBase es privado de Empleado: la cápsula del acto 1 sigue funcionando.
