Parte 1 · El for en cinco minutos

De esto hablamos de pasada el lunes 14. Aqui lo vas a escribir. Un arreglo guarda varios valores en cajitas numeradas, y el for es la forma de pasar por todas.

las posicionesint[] notas = { 7, 9, 5, 10, 8 }; posicion: 0 1 2 3 4 notas.length es 5 valor: 7 9 5 10 8 la ultima posicion es 4

La primera posicion es 0 y la ultima es length - 1. Por eso la condicion del for lleva < y no <=: si escribes <= le pides a Java la cajita 5, que no existe, y truena con ArrayIndexOutOfBoundsException.

Forma 1 · el for clasico, cuando necesitas la posicion

for (int i = 0; i < numeros.length; i++) {
    total = total + numeros[i];
}
//   ^empieza    ^mientras se cumpla   ^suma 1 cada vuelta

i es la posicion, no el valor. El valor que vive ahi es numeros[i]. Es el EJEMPLO A del archivo, ya resuelto: leelo antes de empezar.

Forma 2 · el for-each, cuando solo te importa el valor

for (int valor : numeros) {
    if (valor > umbral) {
        cuantos = cuantos + 1;
    }
}

Se lee "para cada valor de numeros". No tienes la posicion, y no siempre hace falta. Es el EJEMPLO B.

Cual uso

Si necesitas saber en que posicion estas (buscar un indice, construir otro arreglo al reves), usa el clasico. Si solo vas a mirar los valores (sumar, contar, comparar), el for-each se lee mejor.

Lo que mas truena

  • ArrayIndexOutOfBoundsException: pediste una posicion que no existe. Revisa el < de tu for.
  • El promedio sale sin decimales: estas dividiendo entero entre entero. Convierte uno a double.
  • NullPointerException en el 1 o el 5: te faltó crear el arreglo con new o devolverlo.
  • El aviso de que modificaste el original en el 5: construye un arreglo nuevo, no reacomodes el que recibiste.
