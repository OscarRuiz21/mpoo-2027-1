La idea de hoy

Una clase abstracta dice qué es un objeto; una interfaz dice qué sabe hacer. Una canción es un contenido y sabe descargarse. Una app no es un contenido, pero también sabe descargarse: por eso una canción y una app pueden ir en la misma lista de descargas.

Cada clase de hoy se decide con tres preguntas. Esta tabla es el mapa de la práctica:

Clase¿Se reproduce?¿Se descarga?¿Se califica?Por eso su primera línea es
Cancion✔✔✘public class Cancion extends Contenido implements Descargable
Video✔✘✔public class Video extends Contenido implements Calificable
Pelicula✔✔✔ (lo hereda de Video)la escribes tú en la Parte B
Podcast✔✔✔la escribes tú en la Parte C
App✘✔✔la escribes tú en la Parte C

La regla para leerla: ✔ en «se reproduce» se vuelve extends Contenido; ✔ en «se descarga», implements Descargable; ✔ en «se califica», implements Calificable. Si una clase tiene dos interfaces, van separadas por coma.

Clase abstracta contra interfaz

Ojo con el manual. La guía 11 del MADO-21 dice que una interfaz es «una clase abstracta pura» y que todos sus métodos son abstractos. Eso era cierto hasta Java 7. Desde Java 8 una interfaz puede tener métodos default, con cuerpo, como viste el lunes. La diferencia que sí importa hoy es la de la tabla: la interfaz no guarda datos ni tiene constructor.

Parte A · Ejemplo guiado: el contenido, la primera interfaz y la canción

Esta parte trae el código completo. Escríbelo en tu proyecto (no lo pegues: al teclearlo lo entiendes) y lee lo que explica cada paso.

A1 · Lo que todos son: Contenido

clase abstractamétodo abstractoconstructor protectedatributos final

Crea Contenido.java:

package streaming;

// Contenido: todo lo que se puede reproducir en la plataforma.
// Es abstracta: no existe "un contenido" a secas; siempre es una cancion, un video o un podcast.
public abstract class Contenido {

    private final String titulo;
    private final int minutos;

    protected Contenido(String titulo, int minutos) {
        this.titulo = titulo;
        this.minutos = minutos;
    }

    // Todo contenido se reproduce, pero cada hija dice como
    public abstract String reproducir();

    public String getTitulo() {
        return titulo;
    }

    public int getMinutos() {
        return minutos;
    }
}
  • Es abstracta porque en la plataforma no existe «un contenido» a secas: siempre es una canción, un video o un podcast. Es lo más general de la jerarquía.
  • reproducir() es abstracto: no tiene cuerpo, termina en ;. Dice «todo contenido se reproduce», pero cada hija dice cómo.
  • Los atributos son final: el título y los minutos se asignan una vez, en el constructor, y ya no cambian.

A2 · Lo que algunos saben hacer: la interfaz Descargable

interfacemétodo abstracto implícito

Crea Descargable.java (en IntelliJ: New → Java Class → Interface):

package streaming;

// Descargable: lo que se puede bajar al celular para verlo sin internet.
public interface Descargable {

    // Cuantos megas ocupa al bajarlo
    double megas();
}
  • Dice una promesa: «lo que sea descargable sabe decir cuántos megas ocupa». No dice cómo se calcula.
  • megas() no lleva public ni abstract: en una interfaz, todo método sin cuerpo es público y abstracto solo por estar ahí.
  • No tiene atributos ni constructor: la interfaz no sabe cuántos minutos dura nada. Solo promete.

A3 · Es un contenido y sabe descargarse: la Cancion

extendsimplementssuper(...)@Override

Crea Cancion.java:

package streaming;

// Cancion: se reproduce y se descarga. No se califica.
public class Cancion extends Contenido implements Descargable {

    public Cancion(String titulo, int minutos) {
        super(titulo, minutos);
    }

    @Override
    public String reproducir() {
        return "Sonando la cancion " + getTitulo();
    }

    // 1 mega por minuto
    @Override
    public double megas() {
        return getMinutos() * 1.0;
    }
}
  • Lee la primera línea en voz alta: «Cancion es un Contenido y sabe descargarse». extends va primero y implements después.
  • Por eso tiene dos obligaciones: reproducir(), que le exige Contenido, y megas(), que le exige Descargable. Las dos con @Override.
  • El constructor le pasa el título y los minutos a la madre con super(...), como en la P10.

Si se te olvida megas(), la interfaz te lo cobra:

salesrc/streaming/Cancion.java:4: error: Cancion is not abstract and does not override abstract method megas() in Descargable public class Cancion extends Contenido implements Descargable { ^ 1 error

Y si lo escribes sin public: la interfaz lo prometió público, y la clase no puede cerrarlo.

✓El patrón que acabas de seguir

  1. Primera línea: extends la madre (lo que es) e implements las interfaces (lo que sabe hacer).
  2. Constructor: llama a super(...).
  3. Un @Override por cada obligación: los métodos abstractos de la madre y los de cada interfaz.

Parte B · El video y la película final

B1 · La segunda interfaz: Calificable

interfacedos métodos

Crea Calificable.java:

package streaming;

// Calificable: lo que la gente puede calificar con estrellas.
public interface Calificable {

    // Recibe de 1 a 5 estrellas; cualquier otro numero se rechaza
    void calificar(int estrellas);

    // El promedio de las estrellas recibidas (0 si nadie ha calificado)
    double promedio();
}

B2 · El Video (completo)

implementsthrowIllegalArgumentException

Crea Video.java. Un video de la plataforma se ve en línea: se reproduce y se califica, pero no se descarga.

package streaming;

// Video: se reproduce y se califica. No se descarga: se ve en linea.
public class Video extends Contenido implements Calificable {

    private int sumaEstrellas;
    private int calificaciones;

    public Video(String titulo, int minutos) {
        super(titulo, minutos);
    }

    @Override
    public String reproducir() {
        return "Reproduciendo el video " + getTitulo();
    }

    @Override
    public void calificar(int estrellas) {
        if (estrellas < 1 || estrellas > 5) {
            throw new IllegalArgumentException("calificacion invalida: " + estrellas + " (debe ir de 1 a 5)");
        }
        sumaEstrellas += estrellas;
        calificaciones++;
    }

    @Override
    public double promedio() {
        if (calificaciones == 0) {
            return 0;
        }
        return (double) sumaEstrellas / calificaciones;
    }
}
  • Los dos atributos de las estrellas los lleva la clase, no la interfaz: Calificable solo promete calificar y promedio; quien los cumple tiene que guardar la suma y cuántas van.
  • calificar usa throw, como el lunes: si las estrellas no van de 1 a 5, no las suma. Lanza una IllegalArgumentException con un mensaje y el método se corta ahí. Quien llamó decide qué hacer (eso lo haces tú en la Parte D).
  • promedio convierte a double antes de dividir, para que 9 / 2 dé 4.5 y no 4. Si nadie ha calificado, devuelve 0 en vez de dividir entre cero.

Pista 1 · Sin extends

Una app no se reproduce, así que no es un contenido: su primera línea es public class App implements Descargable, Calificable. Sin extends.

Pista 2 · Sin super

Como no hereda de Contenido, no hay super(titulo, minutos) ni getTitulo(). El constructor guarda sus propios atributos: this.nombre = nombre; y this.tamanio = tamanio;. Y megas() solo devuelve tamanio.

D1 · Las calificaciones del grupo: try-catch

try-catchgetMessage()

El grupo calificó el podcast con 5, 6, 4, 0, 3. El 6 y el 0 no valen. Primero haz la prueba ingenua: en el hueco D1 escribe solo podcast.calificar(e);, compila y corre. El programa truena en el 6 y ya no sigue:

saleException in thread "main" java.lang.IllegalArgumentException: calificacion invalida: 6 (debe ir de 1 a 5) at streaming.Podcast.calificar(Podcast.java:27) at streaming.Main.main(Main.java)

Es lo mismo que el menú del lunes: una entrada mala tira todo el programa. Tu tarea: que el 6 y el 0 se rechacen con un aviso y el programa siga con las demás. El aviso es "Rechazada: " más el mensaje de la excepción.

Pista 1 · La forma

try envuelve lo que puede fallar; catch dice qué hacer si falla. Si no falla, el catch no corre.

Pista 2 · El tipo y el mensaje

La traza dice qué excepción es: IllegalArgumentException. Si la atrapas como ex, su mensaje sale con ex.getMessage().

Pista 3 · El esqueleto
        for (int e : estrellas) {
            try {
                ___
            } catch (___ ex) {
                System.out.println("Rechazada: " + ___);
            }
        }

D2 · ¿Qué se califica?: instanceof

instanceofdowncast

En la maratón, unos contenidos se califican y otros no. Por cada c de la maratón: si es Calificable, imprime su título y su promedio; si no, su título y no se califica. Mira la salida esperada abajo para el formato exacto.

Pista 1 · La pregunta

c instanceof Calificable pregunta por el objeto, no por la variable: da true para el video, la película y el podcast, y false para la canción.

Pista 2 · Llegar a promedio()

La variable c es Contenido, y Contenido no tiene promedio(). Necesitas una variable Calificable: un downcast, como en la P10: Calificable k = (Calificable) c;. Java 21 deja hacer la pregunta y el molde en una sola línea: if (c instanceof Calificable k), y adentro del if ya existe k. Cualquiera de las dos vale.

Pista 3 · El esqueleto
        for (Contenido c : maraton) {
            if (c instanceof ___ k) {
                System.out.println(c.getTitulo() + ": " + ___ + " estrellas");
            } else {
                System.out.println(___ + ": no se califica");
            }
        }

¿No que instanceof era lo malo?

En la P10 la cadena de instanceof preguntaba «¿qué clase eres?» para decidir por el objeto cómo golpear: eso lo resuelve el polimorfismo. Aquí preguntas «¿sabes calificarte?», una capacidad que no todos tienen. La alternativa sería poner promedio() en Contenido, y entonces una canción tendría que inventarse estrellas.

E1 · Nadie hereda de una película

final cierra la jerarquía: Pelicula es el último eslabón. ¿Y si quieres películas de terror? El género es un dato, no una clase: sería un atributo genero en Pelicula. Borra el archivo.

E2 · Una interfaz no se instancia

Una interfaz es una promesa, no una cosa: no hay «un descargable» a secas, como no hay «un contenido» a secas. Borra la línea.

  • El choque de dos default: agrega a las dos interfaces un default String resumen(), una que devuelva "se descarga" y otra "se califica". Compila:

Si algo truena

No compila

  • ... is not abstract and does not override abstract method ...: a esa clase le falta un método que le exige su madre o una de sus interfaces. El mensaje dice cuál y de quién.
  • attempting to assign weaker access privileges; was public: escribiste un método de la interfaz sin public.
  • cannot find symbol en calificar o promedio: esa clase no sabe calificarse. ¿Tu Pelicula dice extends Video? ¿Tu Podcast dice implements ..., Calificable?
  • cannot find symbol en tutorial, peli, podcast o mapa: encendiste una parte del Main antes que la anterior. Se encienden en orden: B, C, D.
  • ... is abstract; cannot be instantiated: hay un new de Contenido, Descargable o Calificable.
  • illegal start of expression justo al final de una parte del Main: borraste la línea de arriba de esa parte pero no la de abajo. Borra las dos.

Compila, pero algo sale distinto

  • Un promedio sale 4.0 en vez de 4.5: dividiste dos int. Convierte a double antes de dividir.
  • El podcast sale con 3.6 estrellas: el 6 y el 0 se sumaron. Falta la condición en calificar (paso B2).
  • El programa se detiene en «Exception in thread main»: la llamada a calificar de la Parte D1 no está dentro del try.
  • Encendiste una parte y no sale nada nuevo: borraste la línea de abajo pero no la de arriba, y el comentario se sigue hasta la parte siguiente. Borra las dos.
  • Las descargas no dan 2854.0: revisa las reglas de megas de las tarjetas: 1, 25 y 0.5 por minuto, y la app su tamaño.
