El enunciado

En el Andén 3 de una paquetería hay una estación de clasificación. La estación tiene un nombre y tiene instalados uno o más sensores y uno o más actuadores (le caben hasta cinco de cada uno).

Todo dispositivo tiene un identificador que nunca cambia (S1, A2…) y su propia batería, que se crea con él y se gasta con el uso. No existe un "dispositivo" a secas: es un sensor o un actuador.

Un sensor recibe una señal, la mide en su unidad y dice si hay alerta. Hay tres: el de presencia (la distancia al paquete, en cm; alerta si está atorado a menos de 2 cm), el de peso (en kg; alerta si pasa su límite) y el de temperatura del motor (en grados, con una calibración; alerta si pasa su máxima).

Un actuador se enciende y se apaga, y reacciona a lo que dicen los sensores. Hay tres: la banda transportadora (avanza o se detiene), el semáforo (tiene tres luces, roja, amarilla y verde, que se fabrican con él) y la alarma (suena a un volumen de 0 a 10).

En cada ciclo, la estación lee todos sus sensores; si alguno da alerta, la banda se detiene, el semáforo se pone en rojo y suena la alarma. Si un sensor sale a mantenimiento, sigue existiendo y se puede volver a instalar.

Bateria: sin public, a propósito

package dispositivos;

// sin public: solo el paquete dispositivos la ve
class Bateria {
    private int carga;

    Bateria(int carga) {
        if (carga < 0) {
            this.carga = 0;
        } else if (carga > 100) {
            this.carga = 100;
        } else {
            this.carga = carga;
        }
    }

    int getCarga() {
        return carga;
    }

    void descargar(int puntos) {
        carga = Math.max(0, carga - puntos);
    }
}

Nadie fuera de dispositivos puede ver la batería, ni hacer new Bateria(...). Solo el dispositivo la usa.

Dispositivo: abstracta, con composición y this(...)

package dispositivos;

public abstract class Dispositivo {
    private final String id;
    private final Bateria bateria;

    public Dispositivo(String id, int carga) {
        this.id = id;
        // composición: la batería nace y muere con el dispositivo
        this.bateria = new Bateria(carga);
    }

    // sobrecarga: sin carga, nace al 100
    public Dispositivo(String id) {
        this(id, 100);
    }

    public String getId() {
        return id;
    }

    public int getCarga() {
        return bateria.getCarga();
    }

    // solo las hijas gastan batería
    protected void gastar(int puntos) {
        bateria.descargar(puntos);
    }

    @Override
    public String toString() {
        return id + " (" + bateria.getCarga() + "%)";
    }
}

Dos constructores con el mismo nombre y distintos parámetros: eso es sobrecarga. El segundo no repite nada: le pasa el trabajo al primero con this(id, 100), que tiene que ser su primera línea.

Sensor: abstracta, hija de otra abstracta

package dispositivos;

public abstract class Sensor extends Dispositivo {
    private final String unidad;
    private double senal;

    public Sensor(String id, String unidad, int carga) {
        super(id, carga);
        this.unidad = unidad;
    }

    public Sensor(String id, String unidad) {
        this(id, unidad, 100);
    }

    public String getUnidad() {
        return unidad;
    }

    // Main simula lo que llega del mundo real
    public void recibir(double senal) {
        this.senal = senal;
    }

    // las hijas leen la señal cruda
    protected double getSenal() {
        return senal;
    }

    public abstract double medir();

    public abstract boolean hayAlerta();

    // final: ninguna hija cambia cómo se reporta una lectura
    public final String leer() {
        gastar(1);
        String texto = getId() + " mide " + medir() + " " + unidad;
        if (hayAlerta()) {
            texto = texto + " ALERTA";
        }
        return texto;
    }

    @Override
    public String toString() {
        return "Sensor " + super.toString();
    }
}

leer() es final y llama a medir() y hayAlerta(), que todavía no existen: cada hija pone su versión. getSenal() es protected porque solo las hijas la necesitan, y ellas viven en otro paquete.

SensorTemperatura: la primera hoja

package sensores;

import dispositivos.Sensor;

public class SensorTemperatura extends Sensor {
    private double calibracion;
    private double maxima;

    public SensorTemperatura(String id, double calibracion, double maxima) {
        super(id, "C");
        this.calibracion = calibracion;
        this.maxima = maxima;
    }

    @Override
    public double medir() {
        return getSenal() + calibracion;
    }

    @Override
    public boolean hayAlerta() {
        return medir() > maxima;
    }

    @Override
    public String toString() {
        return super.toString() + " temperatura, max " + maxima;
    }
}

        anden.instalar(termo);
        anden.instalar(banda);
        anden.instalar(semaforo);
        anden.instalar(alarma);

        bascula.recibir(18500);
        termo.recibir(41.5);
        anden.ciclo();

Lo que más truena

No compila

  • SensorPresencia is not abstract and does not override abstract method hayAlerta() in Sensor: a tu sensor le falta uno de los métodos abstractos del padre. Una hija concreta tiene que escribir todos: medir() y hayAlerta().
  • Sensor is abstract; cannot be instantiated: Sensor es abstracta: no hay sensores a secas, solo de presencia, de peso o de temperatura.
  • call to this must be first statement in constructor: el this(...), igual que el super(...), tiene que ser la primera línea del constructor.
  • senal has private access in Sensor: la señal es privada de Sensor. Las hijas la leen con getSenal(), que es protected.
  • Semaforo is not public in actuadores; cannot be accessed from outside package: a la clase le falta public. Sin modificador solo la ve su paquete, y Main vive en estacion.
  • Bateria is not public in dispositivos; cannot be accessed from outside package: quisiste crear una batería desde otro paquete. La batería la crea Dispositivo y nadie más.
  • leer() in SensorPeso cannot override leer() in Sensor: leer() es final en Sensor: las hijas no la sobrescriben, solo escriben medir() y hayAlerta().
  • cannot find symbol: falta un import. Cada clase de otro paquete se importa por su nombre completo, por ejemplo import actuadores.Alarma;.

Compila, pero la salida no es la de la guía

  • En el ciclo 3 vuelve a salir S2 y falta S3: tu retirar resta el contador pero no recorre los sensores que siguen un lugar a la izquierda.
  • En el ciclo 2 la banda sigue avanzando: tu ciclo() pregunta por la alerta dentro del mismo for de los actuadores, o se queda solo con la del último sensor. Primero se leen todos los sensores, luego reaccionan los actuadores.
  • Sale Regresa: null: tu retirar borra el sensor antes de guardarlo en una variable para devolverlo.
  • La alarma dice volumen 15: el constructor de Alarma no valida.
