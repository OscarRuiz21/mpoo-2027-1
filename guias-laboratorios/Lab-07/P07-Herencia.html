Parte 1 · Animales, junto con el profesor

Animal nombre, edad sonido() da "..." ├── Perro + raza sonido() da "Guau" │ └── PerroGuia + asistido (sonido lo hereda de Perro) └── Gato + interior sonido() da "Miau"

El profesor teclea Animal y Perro en el proyector y tú las tecleas con él. Así quedan:

public class Animal {

    // private: ni sus hijos los tocan
    private String nombre;
    private int edad;

    public Animal(String nombre, int edad) {
        this.nombre = nombre;
        // la cápsula: el constructor valida
        if (edad < 0) {
            this.edad = 0;
        } else {
            this.edad = edad;
        }
    }

    public String getNombre() {
        return nombre;
    }

    public int getEdad() {
        return edad;
    }

    public String sonido() {
        return "...";                   // un animal a secas
    }

    // sobrescribe el toString de Object
    @Override
    public String toString() {
        return nombre + ", edad " + edad;
    }
}
// un Perro ES UN Animal
public class Perro extends Animal {

    // solo lo nuevo: nombre y edad vienen de Animal
    private String raza;

    public Perro(String nombre, int edad, String raza) {
        // SIEMPRE la primera línea: Animal guarda lo suyo
        super(nombre, edad);
        this.raza = raza;               // y luego Perro, lo suyo
    }

    public String getRaza() {
        return raza;
    }

    @Override
    public String sonido() {
        return "Guau";
    }

    @Override
    public String toString() {
        // reutiliza el del padre y le agrega
        return super.toString() + " | " + raza;
    }
}

Lo que más truena

No compila

  • constructor Personaje in class Personaje cannot be applied to given types: a tu Caballero le falta super(nombre, vida);. Si no lo escribes, Java pone super() sin argumentos, y Personaje no tiene ese constructor.
  • call to super must be first statement in constructor: el super(...) tiene que ser la primera línea del constructor, antes de guardar lo tuyo.
  • nombre has private access in Personaje: quisiste usar nombre desde Caballero. Es privado del padre: usa super.toString() o getNombre(). Lo mismo con fuerza desde Paladin: usa super.atacar().
  • method does not override or implement a method from a supertype: escribiste mal el nombre (tostring, Atacar) y el @Override te avisó. Para eso está.

Compila, pero la salida no es la de la guía

  • A Lunara le falta | fe 40: tu toString de Paladin está mal escrito y no tiene @Override, así que se usa el del padre sin avisar. Ponle @Override y verás el error.
  • Lunara ataca con 20 en vez de 42: tu atacar() de Paladin no llama a super.atacar().
  • El Aldeano sale con vida 150: el constructor de Personaje no valida.
